Responder com suas próprias palavras:

1. Como vocês testariam se um requisito foi atendido no desenvolvimento de um sistema? Esse requisito poderia ser interpretado de mais de um jeito? Por quem, e como?

2. Para um sistema de delivery de comida, escrevam 4 requisitos funcionais seguindo o modelo “O sistema deve…”. Depois, troquem com a dupla ao lado e apontem se algum requisito ficou ambíguo ou difícil de testar.

3. Já usou algum app que travava demais ou era muito lento? Isso seria falha de que tipo de requisito? Por que seria um erro dizer que RNF é ‘menos importante’ que RF?

4. Uma lista com 6 requisitos de um aplicativo de transporte. Classificar cada um como RF ou RNF e, para os RNFs, identificar a categoria (desempenho, segurança, usabilidade…).

Respostas:


1. Testaria pra ver se tá funcionando como foi pedido. Pode sim ser entendido de outro jeito se estiver mal explicado.

2.

* O sistema deve permitir fazer pedido.
* O sistema deve mostrar o preço.
* O sistema deve aceitar pagamento.
* O sistema deve mostrar onde está o pedido.

Pode ter dúvida em alguns, tipo como vai mostrar onde está o pedido.

3. Sim, já usei app lento. É problema de RNF, de desempenho. RNF não é menos importante porque se o app for ruim de usar ou lento, ninguém vai querer usar.

4.

1. Fazer corrida — RF
2. Ver motorista — RF
3. Carregar rápido — RNF (desempenho)
4. Proteger os dados — RNF (segurança)
5. Ser fácil de usar — RNF (usabilidade)
6. Não ficar caindo — RNF (disponibilidade)
